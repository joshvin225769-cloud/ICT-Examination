# Verification record

Evidence is generated by actual local test runs, not hand-entered pass claims.

## Reproduce

```sh
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:browser
npm audit
```

API tests start isolated MongoDB 8.2.6 using `mongodb-memory-server`. Browser checks run the production React bundle through Express with a separate isolated database. No production credentials, existing records, or real personal data are needed. Browser screenshots use fictional students and staff. These checks require downloading MongoDB and Chromium on a clean machine.

## Evidence files

- `evidence/api-results.json`: named successful API scenarios and actual run timestamp.
- `evidence/browser-results.json`: named browser scenarios, captured screens, axe findings, and uncaught JavaScript errors.
- `screenshots/`: desktop (1440px) and mobile (390px) captures.

API cases cover authentication, password hashing, cookie settings, duplicate registration, role escalation, missing sessions, CRUD persistence, scoped statistics, ownership for every protected operation, admin permissions, non-open edit restrictions, filters, pagination, validation, malformed requests, safe errors, origin protection, and rate limiting.

Browser cases exercise registration, login/logout, real create/edit/comment/delete, admin status updates, student visibility of those updates, deep-link refresh, pagination/filter/search, mobile layouts, a simulated API error/retry, and automated accessibility scans. No production outage was induced; the error-state screenshot uses an explicitly intercepted local API response.

## Limitations

Automated axe checks are helpful but are not a complete accessibility certification. Chromium is verified; Safari/Firefox, screen-reader testing, production load, disaster recovery, and live Atlas/HTTPS flows remain to be assessed. No response-time or user-satisfaction improvement is claimed from the small synthetic dataset. The suite tests intended features, not production capacity.

## Issues found and addressed

1. Early muted text and status badges did not meet automated contrast requirements. Secondary text and badge palettes were darkened and rechecked across every captured screen.
2. Initial dependency audit identified advisories affecting the earlier router version. React Router was upgraded to a patched 7.x release and the application was rebuilt and browser-tested.
3. Post-logout notifications could remain visible after the next sign-in. The unnecessary logout toast was removed so session transitions and screenshots stay clear.
4. Linux CI exposed a query-state race that could reset a draft search when an unrelated filter changed. Search synchronization now depends only on the applied search term, and the browser scenario checks that draft text survives a status-filter change.
5. A Windows-generated dependency lockfile initially omitted Linux-native optional packages. Regenerating it without an installed dependency tree restored cross-platform package entries, and a fresh Windows install/build was verified before rerunning Linux CI.
